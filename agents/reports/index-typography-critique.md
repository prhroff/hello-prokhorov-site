# Index: типографская критика (10 окт 2026)

Объект: блок Index (`.idx`) на главной (`/ru/#index`) и на `/info/#index`. Смотрел на 375, 768, 1024, 1440 и 1920, в 1x и 2x, с reduced motion и без. Код: `new-test-ru/css/main.css` (блок «Index (home and /info/»), `project_index()` в `scripts/build-html.py`. Референс: программка Kulturloft (`images/2.jpg`).

Только типографика: ссылок, hover, построчной анимации и картинок за курсором здесь нет.

Скриншоты (scratchpad/shots/):
- как сейчас: `critic-info-en-1440.png`, `critic-head-home-ru-1440.png`, `critic-info-en-1024.png`, `critic-info-en-768.png`, `critic-home-ru-375.png`
- линейки в 1x: `critic-rules-1x-reduce.png` и `critic-rules-1x-no-preference.png`
- с правками ниже (внедрены через инъекцию CSS, файлы сайта не трогал): `critic-after-info-1440.png`, `critic-after-info-1920.png`, `critic-after-home-ru-375.png`, `critic-rules2-no-preference.png`

Цифры даны для 1440, где кегль строки 21.6px (3.6cqi от 600px).

## 1. Колонка года слишком широкая, и имена не стоят на сетке заголовка
**Что видно.** Колонка года `4.4em` (95px), а «2026» занимает 2.5em (54px). Между годом и именем дыра в 54px, то есть 2.5em. В референсе дата отделена от имени примерно на ширину пробела, поэтому строка читается одной фразой: «07.02.20 Bersærk». У нас год висит отдельной колонкой. Колонку раздувает одна строка, «2023–24» (4.24em = 91px). Ещё одно: имена начинаются на 108px, а заголовок секции «Index» / «Все проекты» на 52px (`.block__no` 2.9em от 18px). Две левые кромки разошлись на 56px, и это прямо под заголовком.
**Почему важно.** Это самый заметный дефект блока. Программка держится на плотной связке «дата + имя», а здесь вместо неё получилась таблица с пустым столбцом.
**Правка.**
- Контент (решает Артём): в Index дать «2023–24» как один год («2024»), как у остальных 34 строк. Без этого колонку уже, чем 4.3em, не сделать.
- CSS: колонку по «2026», а номер в заголовке этого блока растянуть так, чтобы «Index» встал ровно над именами:
```css
.idx-block > * { --fs: clamp(17px, 3.6cqi, 30px); }
.idx__row { font-size: var(--fs); grid-template-columns: 2.5em minmax(0, 1fr); column-gap: 0.6em; }
.idx-block .block__no { width: calc(var(--fs) * 3.1); }   /* = 2.5em + 0.6em кегля строки */
```
Цена: на 1920 зазор «(02) → Index» в заголовке вырастает до 90px. Зато название и имена стоят на одной вертикали, и это того стоит (см. `critic-after-info-1920.png`).

## 2. Поднятая пометка не стоит на линии прописных и «плавает» с шириной
**Что видно.** У `.idx__note` `top: -1.15em` считается в ems самой пометки, а её кегль упирается в минимум 10px. На 1440 верх прописных пометки лежит на 3px выше верха прописных имени: «(Website design)» торчит над «Supaminds». На 1920 наоборот, пометка на 1.5px ниже. В референсе верх пометки ровно по линии прописных.
**Почему важно.** Это главный приём блока («маленькая поднятая пометка»), и как раз он стоит неточно, причём на каждой ширине по-разному.
**Правка.** Сдвиг считать от разницы кеглей, с высотой прописных Inter 0.7275:
```css
.idx-block > * { --n: max(10px, calc(var(--fs) * 0.36)); --cap: 0.7275; }
.idx__note { font-size: var(--n); top: calc((var(--n) - var(--fs)) * var(--cap)); margin-left: 0.25em; }
```
Тогда верх пометки совпадает с верхом прописных имени на любой ширине. Зазор `0.25em` (2.5px вместо 1.5px) нужен, чтобы скобка не липла к последней букве («Studio(Website)»).

## 3. Знак ® даёт второй ярус надстрочника
**Что видно.** Перед пометкой у Powermatic, Prokhorov, Visual Hunters, Contour Office, Specter Studio и Loglark стоит `.r` от 0.5em (10.8px, это крупнее пометки в 10px) с `vertical-align: 0.82em`. Получаются два надстрочных элемента разного кегля на разной высоте: ® ниже, скобка выше. Выглядит как опечатка («Technologies®(Design…»).
**Почему важно.** В строках с ® ломается ровная «верхняя полка» пометок, а это шесть строк из 35, все в верхней половине списка.
**Правка.** В Index поставить ® на ту же полку и в тот же кегль, что пометку:
```css
.idx .r { font-size: var(--n); vertical-align: 0; position: relative; top: calc((var(--n) - var(--fs)) * var(--cap)); }
.idx .r + .idx__note { margin-left: 0.2em; }
```
Вариант радикальнее: в списке ® не показывать (`.idx .r { display: none; }`), в референсе знаков нет. Это решение Артёма.

## 4. Линейки 1.5px: у большинства посетителей мутная двойная линия
**Что видно.** При reduced motion линейка рисуется бордером и в 1x даёт чистый 1px #121212. Без reduced motion (то есть у большинства) она рисуется градиентом `100% 1.5px` на дробной координате, и в 1x получается 1px чёрного плюс 1px серого (136). Мерил пикселями: `critic-rules-1x-no-preference.png`. В 2x она становится 3px, то есть заметно толще, чем на макете.
**Почему важно.** Тёмные линейки здесь главный графический элемент, а они серые и размытые. Ещё и видны по-разному в зависимости от настройки движения.
**Правка.** Целый 1px везде. Линии, которые прорисовываются, делать фоном псевдоэлемента, а не градиентом: прямоугольник элемента браузер прибивает к пикселю, градиент нет. Движение то же самое, только чёткое (проверено, `critic-rules2-no-preference.png`):
```css
.idx { border-bottom: 1px solid var(--fg); }
.idx__row { position: relative; border-top: 1px solid var(--fg); }
.motion-ok .idx__row, .motion-ok .idx__row:last-child { background: none; }
.motion-ok .idx__row::before,
.motion-ok .idx__row:last-child::after { content: ""; position: absolute; left: 0; height: 1px; width: 0; background: var(--fg); transition: width 1.2s var(--ease); }
.motion-ok .idx__row::before { top: -1px; }
.motion-ok .idx__row:last-child::after { bottom: -1px; }
.motion-ok .is-in .idx__row::before,
.motion-ok .is-in .idx__row:last-child::after { width: 100%; }
```
(Прозрачные `border-color` в `.motion-ok` оставить как есть.)

## 5. Строка набрана низко, и выносные почти касаются линейки
**Что видно.** Отступы `0.3em сверху / 0.1em снизу`. От линейки до верха прописных 11px, от базовой линии до следующей линейки 6.7px. Нижние выносные g, p, y заканчиваются в 2px над линейкой: «Technologies», «Playgram», «Supaminds».
**Почему важно.** В программке строка зажата между линейками, но буквы их не касаются. У нас низ строки тесный, верх пустой, и ритм столбца получается тяжёлым книзу.
**Правка.** Той же высотой строки (1.55em) поставить прописные по центру между линейками:
```css
.idx__row { padding: 0.2em 0; }
```
Получится 8.9px над прописными и 8.9px под базовой линией, у выносных 4.4px до линейки.

## 6. Картинки выше прописных и не стоят ни на одной линии
**Что видно.** У `.idx__thumb` высота 1.05em и `vertical-align: -0.12em`. Картинка вылезает на 0.2em над прописными и на 0.12em под базовую линию: до верхней линейки 6.7px, до нижней 4px. Её верх не совпадает ни с прописными имени, ни с пометкой.
**Почему важно.** В референсе фото ведёт себя как ещё одно «слово» в строке. У нас это плашка, которая распирает строку.
**Правка.** Картинка ровно в высоту прописных, на базовой линии, 16:9:
```css
.idx__thumb { vertical-align: 0; width: 1.3em; height: calc(var(--cap) * 1em); margin-left: 0.45em; }
```
Верх картинки совпадает с верхом прописных и пометки, низ с базовой линией.

## 7. Трекинг имён шире, чем у всего остального крупного текста на сайте
**Что видно.** У `.idx__row` `letter-spacing: -0.02em` при кегле 22–30px. Заголовок прямо над списком набран с −0.035em, имена в карточках работ с −0.04em, основной текст с −0.03em. Имена в Index выглядят рыхлее заголовка, который при этом мельче.
**Правка.**
```css
.idx__row { letter-spacing: -0.03em; }
```
Год остаётся на `tabular-nums`, и −0.03em ему не вредит.

## 8. Телефон и узкая колонка: имя не крупное, два почти одинаковых мелких кегля, пустая колонка
**Что видно (375 и 768, контейнер уже 460px).** Имя 17px, то есть того же кегля, что заголовок секции, и контраст программки «крупное имя» пропадает. Год 12.2px (0.72em), пометка 11px: два кегля, которые отличаются на 1px и выглядят как ошибка. Колонка года 3.4em (58px) при ширине «2026» около 30px оставляет 38px пустоты, и имена опять не на вертикали заголовка (68px против 49px). Пометка чёрная, хотя на телефоне она отдельная вторая строка и должна быть тише.
**Правка.**
```css
@container (max-width: 459px) {
  .idx-block > * { --fs: 20px; }
  .idx-block .block__no { width: 2.9em; }
  .idx__row { grid-template-columns: calc(2.9 * var(--t-head)) minmax(0, 1fr); column-gap: 0; padding: 0.3em 0 0.35em; }
  .idx__year { font-size: 11px; letter-spacing: 0; }
  .idx .idx__note, .idx .r + .idx__note { top: 0; margin: 0.25em 0 0; font-size: 11px; color: var(--mute); }
  .idx .r { top: 0; font-size: 0.45em; vertical-align: 0.82em; }
}
```
Имена встают ровно под «Все проекты», год и пометка набраны одним мелким кеглем, имя 20px (`critic-after-home-ru-375.png`). При «2024» вместо «2023–24» колонка помещается и тут (иначе у диапазона в 11px 46px при колонке 49px, впритык).

## 9. Шаг строк в 1x неровный: 34/35/34/35px
**Что видно.** Кегль из `cqi` дробный (21.59px), и высота строки тоже дробная (34.45px). Линейки в 1x ложатся через 34 и 35px попеременно. На 35 строках это заметно как лёгкая «рябь» столбца.
**Правка.** Округлить кегль и отступы до пикселя:
```css
.idx-block > * { --fs: round(clamp(17px, 3.6cqi, 30px), 1px); }
.idx__row { padding: round(0.2em, 1px) 0; line-height: round(1.15em, 1px); }
```
(`round()` поддерживают Chrome 125+, Safari 15.4+ и Firefox 118+. В старых браузерах правило просто отбросится и останется дробный вариант, поэтому строку с `clamp()` без `round()` оставить выше как запасную.)

## 10. Картинки спорят по тону (по желанию)
**Что видно.** Ярко-зелёная Renovate и почти чёрные Powermatic и Lattice рядом со светлыми Luma и Visual Hunters. В 28×16px это читается как цветные кляксы, а не как кадры. В референсе фото приглушённые, почти ч/б, и столбец ровный по тону.
**Правка (обработка картинки, не новая функция):**
```css
.idx__thumb img { filter: grayscale(1) contrast(1.05); }
```
Если Артёму важен цвет Renovate, этот пункт пропустить: 1–9 работают и без него.
